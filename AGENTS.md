# Инструкции для AI-агентов

Проект использует **Feature-Sliced Design (FSD)**. При разработке новых компонентов, фич и страниц строго следуй этой методологии и соглашениям проекта.

## Быстрый старт

1. Определи **слой** и **слайс** (см. таблицу ниже).
2. Создай структуру папок с нужными **сегментами** (`ui`, `model`, `api`, `lib` и т.д.).
3. Реализуй код внутри сегментов.
4. Экспортируй наружу **только через Public API** (`index.ts`).
5. Импортируй из других слоёв **только через Public API** с алиасом `@/`.
6. Запусти `npm run lint` и `npm run typecheck` после изменений.

## Слои (снизу вверх)

| Слой | Путь | Когда использовать |
|------|------|--------------------|
| `shared` | `src/shared/` | Переиспользуемый UI-kit, утилиты, API-клиент, конфиг. Без бизнес-логики. |
| `entities` | `src/entities/` | Бизнес-сущности: User, Product, Order. Отображение и данные сущности. |
| `features` | `src/features/` | Действия пользователя: авторизация, добавление в корзину, лайк. |
| `widgets` | `src/widgets/` | Композитные блоки страницы: хедер, сайдбар, карточка профиля. |
| `pages` | `src/pages/` | Страницы — композиция виджетов и фич. Одна страница = один слайс. |
| `app` | `src/app/` | Инициализация, провайдеры, роутинг, глобальные стили. |

### Правило импортов

Слой может импортировать **только из слоёв ниже** себя:

```
app → pages → widgets → features → entities → shared
```

- `pages` может импортировать `widgets`, `features`, `entities`, `shared`.
- `features` **не может** импортировать `pages` или `widgets`.
- `shared` **не может** импортировать ничего из FSD-слоёв.

ESLint (`@feature-sliced/eslint-config`) автоматически проверяет эти ограничения.

## Куда положить новый код

Перед созданием файла ответь на вопросы:

1. **Это переиспользуемый UI без бизнес-контекста?** → `shared/ui/`
2. **Это данные/отображение одной бизнес-сущности?** → `entities/<entity-name>/`
3. **Это действие пользователя (кнопка + логика)?** → `features/<feature-name>/`
4. **Это самостоятельный блок, собирающий фичи и сущности?** → `widgets/<widget-name>/`
5. **Это целая страница?** → `pages/<page-name>/`
6. **Это глобальная настройка приложения?** → `app/`

Не создавай код вне `src/` (кроме конфигов в корне). Не складывай компоненты в `src/components/` — такой папки нет.

## Структура слайса

### Минимальная структура (UI-компонент)

```
src/pages/home/
├── ui/
│   ├── HomePage.tsx
│   ├── HomePage.module.scss
│   └── index.ts          # Public API сегмента ui
└── index.ts              # Public API слайса
```

### Расширенная структура (при необходимости)

```
src/features/add-to-cart/
├── ui/
│   ├── AddToCartButton.tsx
│   ├── AddToCartButton.module.scss
│   └── index.ts
├── model/
│   ├── useAddToCart.ts
│   └── index.ts
├── api/
│   ├── addToCart.ts
│   └── index.ts
└── index.ts
```

### Сегменты

| Сегмент | Назначение |
|---------|------------|
| `ui` | React-компоненты и их стили |
| `model` | Состояние, хуки, бизнес-логика слайса |
| `api` | Запросы к серверу |
| `lib` | Вспомогательные функции слайса |
| `config` | Конфигурация слайса |

Добавляй только нужные сегменты. Не создавай пустые папки «на будущее».

## Public API

Каждый слайс и сегмент экспортирует наружу **только через `index.ts`**.

```ts
// ✅ Правильно — импорт через Public API
import { HomePage } from "@/pages/home";
import { Button } from "@/shared/ui/button";

// ❌ Неправильно — прямой импорт внутреннего файла
import { HomePage } from "@/pages/home/ui/HomePage";
```

Цепочка реэкспорта:

```ts
// pages/home/index.ts
export { HomePage } from "./ui";

// pages/home/ui/index.ts
export { HomePage } from "./HomePage";
```

В Public API экспортируй только то, что нужно снаружи. Внутренние детали не реэкспортируй.

## Именование

| Элемент | Конвенция | Пример |
|---------|-----------|--------|
| Папка слайса | `kebab-case` | `add-to-cart`, `user-profile` |
| React-компонент | `PascalCase` | `AddToCartButton`, `UserCard` |
| Хуки | `camelCase` с `use` | `useAddToCart`, `useUserData` |
| Утилиты | `camelCase` | `formatPrice`, `parseDate` |
| SCSS-модуль | Рядом с компонентом | `HomePage.module.scss` |

Имя компонента должно совпадать с именем файла: `HomePage.tsx` → `export function HomePage`.

## Стили

- **Глобальные стили** — `src/app/styles/` (normalize, CSS-переменные).
- **Стили компонентов** — CSS Modules: `*.module.scss` рядом с компонентом.
- **Корневой элемент** — класс `.root`.
- **Остальные классы** — по роли: `.title`, `.content`, `.button`.

```tsx
import styles from "./HomePage.module.scss";

export function HomePage() {
  return (
    <div className={styles.root}>
      <h1 className={styles.title}>App</h1>
    </div>
  );
}
```

Не используй глобальные классы для стилей компонентов. Не используй CSS-in-JS — в проекте SCSS Modules.

## Импорты

- Алиас: `@/` → `src/`.
- Порядок импортов (ESLint `import/order`):
  1. `react`
  2. Внешние пакеты
  3. FSD-слои снизу вверх: `@/shared` → `@/entities` → `@/features` → `@/widgets` → `@/pages` → `@/app`
  4. Относительные импорты (`./`, `../`)
  5. Стили (`.scss`, `.module.scss`)
- Между группами — пустая строка.

## React и TypeScript

- Только функциональные компоненты.
- Именованный экспорт (`export function`), не `export default`.
- Строгий TypeScript: не используй `any` без веской причины.
- `useCallback` / `useMemo` — только при реальной необходимости (см. правила проекта).
- Не добавляй комментарии к очевидному коду.

## Пошаговые сценарии

### Новая страница

1. Создай `src/pages/<page-name>/ui/<PageName>.tsx` + `.module.scss`.
2. Создай `src/pages/<page-name>/ui/index.ts` с реэкспортом.
3. Создай `src/pages/<page-name>/index.ts` с реэкспортом из `./ui`.
4. Подключи страницу в `src/app/App.tsx` (или роутер, когда появится).

### Новая фича

1. Создай `src/features/<feature-name>/ui/` с компонентом.
2. При необходимости добавь `model/`, `api/`.
3. Собери Public API в `index.ts` на каждом уровне.
4. Используй фичу в `widgets/` или `pages/`.

### Компонент UI-kit (shared)

1. Создай `src/shared/ui/<component-name>/`.
2. Компонент должен быть **без бизнес-логики** — только presentation.
3. Пропсы типизируй через `type`.

### Новая сущность

1. Создай `src/entities/<entity-name>/`.
2. Сегмент `ui/` — карточка, аватар, превью сущности.
3. Сегмент `model/` — типы, стор, хуки для данных сущности.
4. Сегмент `api/` — запросы, связанные с сущностью.

## Чего не делать

- Не нарушай направление импортов между слоями.
- Не импортируй внутренние файлы слайсов — только Public API.
- Не создавай `index.ts` с `export *` из всего подряд — экспортируй явно.
- Не клади бизнес-логику в `shared/`.
- Не дублируй README или эту инструкцию в других файлах.
- Не добавляй тесты, документацию и зависимости, если пользователь явно не просил.
- Не меняй конфигурацию ESLint/Vite/TypeScript без запроса.
